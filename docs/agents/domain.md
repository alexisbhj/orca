# Domain docs

Use a single-context layout across desktop, mobile and cloud:
`GLOSSARY.md` at the repository root and decisions in `docs/adr/`.

Before exploring, read the glossary and ADRs relevant to the work.
If these files are absent, proceed silently without creating empty files.
Domain modeling creates them when terms or decisions are resolved.

Use the glossary's vocabulary in issues, proposals and tests.
Identify any proposed change that contradicts an existing ADR.
